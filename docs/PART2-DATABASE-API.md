## 2.0 The Single Source of Truth (P1 + P6)

There is exactly **one** authority for the data model and **one** generation step that produces every type the system uses.

```
┌─────────────────────────────┐
│  supabase/migrations/        │   ← SINGLE SOURCE OF TRUTH
│  0001_init.sql               │     (versioned, append-only, in git)
│  0002_add_*.sql              │
└──────────────┬──────────────┘
               │  supabase db push        (applies to DB)
               │  supabase gen types ts   (reads DB → emits TS)
               ▼
┌─────────────────────────────┐
│  packages/shared/src/types/  │   ← GENERATED — never hand-edited
│  database.types.ts           │
└──────────────┬──────────────┘
               │  derive
               ▼
┌─────────────────────────────┐
│  packages/shared/src/schemas/│   ← Zod schemas (runtime validation)
│  *.schema.ts                 │     hand-authored, but typed AGAINST
└──────────────┬──────────────┘     the generated Row types (compile-fails on drift)
               │  consume
               ▼
   API factories · client hooks · forms · tables
```

**Rules (enforced):**
1. No table, column, enum, or policy is created anywhere except a migration file in `supabase/migrations/`.
2. `database.types.ts` is generated by CI and committed. A pre-commit/CI check fails if it is stale relative to the migrations.
3. Hand-written ORM schema definitions are **prohibited.** If Part 1 still shows `db/schema.ts` as "Drizzle schema definitions," that line is superseded — `apps/api/src/db/` contains only the Supabase client + (optionally) a Drizzle **query builder** that imports the generated types; it never re-declares tables.

**Generation commands** (also wired into `turbo` + `scripts/`):
```bash
# Apply pending migrations to the linked Supabase project
supabase db push

# Generate TypeScript types from the live schema → committed file
supabase gen types typescript --linked > packages/shared/src/types/database.types.ts

# CI drift guard (fails if generated types are out of date)
supabase gen types typescript --linked | diff - packages/shared/src/types/database.types.ts
```

## 2.1 Database Schema — Migration `0001_init.sql`

> [!IMPORTANT]
> Save as `supabase/migrations/0001_init.sql`. Apply with `supabase db push` (local) or paste into the Supabase SQL Editor for the first bring-up. This file — not any ORM — defines the data model.

```sql
-- ═══════════════════════════════════════════════════════
-- JARVIS v1.5 — Migration 0001: Initial Schema
-- Supabase (PostgreSQL 15+)
-- ═══════════════════════════════════════════════════════

create extension if not exists "uuid-ossp";
create extension if not exists "pgcrypto";

-- ───────────────────────────────────────────────────────
-- TENANTS
-- ───────────────────────────────────────────────────────
create table public.tenants (
  id          uuid default gen_random_uuid() primary key,
  name        text not null,
  slug        text unique not null,
  plan        text not null default 'free'
              check (plan in ('free', 'pro', 'enterprise')),
  settings    jsonb default '{}'::jsonb,
  created_at  timestamptz default now() not null,
  updated_at  timestamptz default now() not null
);

-- ───────────────────────────────────────────────────────
-- PROFILES (extends auth.users)
-- ───────────────────────────────────────────────────────
create table public.profiles (
  id          uuid primary key references auth.users(id) on delete cascade,
  tenant_id   uuid not null references public.tenants(id) on delete cascade,
  full_name   text,
  avatar_url  text,
  role        text not null default 'owner'
              check (role in ('owner', 'admin', 'member', 'viewer')),
  preferences jsonb default '{}'::jsonb,
  created_at  timestamptz default now() not null,
  updated_at  timestamptz default now() not null

create index idx_profiles_tenant on public.profiles(tenant_id);

-- ───────────────────────────────────────────────────────
-- CHAT SESSIONS / MESSAGES
-- ───────────────────────────────────────────────────────
create table public.chat_sessions (
  id          uuid default gen_random_uuid() primary key,
  tenant_id   uuid not null references public.tenants(id) on delete cascade,
  title       text not null default 'New Chat',

  is_active   boolean default true,
  created_at  timestamptz default now() not null,

create index idx_chat_sessions_tenant on public.chat_sessions(tenant_id);

  tenant_id   uuid not null references public.tenants(id) on delete cascade,
  role        text not null check (role in ('user', 'assistant', 'system', 'tool')),

  model       text,

-- ───────────────────────────────────────────────────────

              check (trigger in ('manual', 'cron', 'webhook', 'event')),
  schedule    text,
  skill_name  text,
  config      jsonb default '{}'::jsonb,
  enabled     boolean default true,
  created_at  timestamptz default now() not null,
  updated_at  timestamptz default now() not null
);
create index idx_workflows_tenant on public.workflows(tenant_id);

create table public.workflow_runs (
  id           uuid default gen_random_uuid() primary key,
  workflow_id  uuid not null references public.workflows(id) on delete cascade,
  tenant_id    uuid not null references public.tenants(id) on delete cascade,
  status       text not null default 'pending'
               check (status in ('pending','running','success','failed','cancelled')),
  output       text,
  error        text,
  started_at   timestamptz default now() not null,
  finished_at  timestamptz,
  duration_ms  integer
);
create index idx_workflow_runs_workflow on public.workflow_runs(workflow_id, started_at desc);
create index idx_workflow_runs_tenant on public.workflow_runs(tenant_id);

-- ───────────────────────────────────────────────────────
-- INTEGRATIONS (MCP connections)
-- Secret material is NEVER stored in `config` in plaintext.
-- See §2.6 — provider tokens go in `secret_ciphertext` (AES-256-GCM).
-- ───────────────────────────────────────────────────────
create table public.integrations (
  id                uuid default gen_random_uuid() primary key,
  tenant_id         uuid not null references public.tenants(id) on delete cascade,
  type              text not null,
  name              text not null,
  status            text not null default 'pending'
                    check (status in ('connected','pending','error','disabled')),
  config            jsonb default '{}'::jsonb,   -- non-secret config only
  secret_ciphertext text,                        -- AES-256-GCM, base64 (see §2.6)
  secret_iv         text,                        -- per-record nonce, base64
  tools             text[] default '{}',
  last_health       timestamptz,
  created_at        timestamptz default now() not null,
  updated_at        timestamptz default now() not null
);
create index idx_integrations_tenant on public.integrations(tenant_id);

-- ───────────────────────────────────────────────────────
-- SKILLS (Hermes learned skills)
-- ───────────────────────────────────────────────────────
create table public.skills (
  id          uuid default gen_random_uuid() primary key,
  tenant_id   uuid not null references public.tenants(id) on delete cascade,
  name        text not null,
  description text,
  content     text not null,

              check (category in ('swe','devops','content','research',

  usage_count integer default 0,
  avg_rating  numeric(3,2) default 0,
  last_used   timestamptz,
  created_at  timestamptz default now() not null,

);

create table public.analytics_events (

create index idx_analytics_type on public.analytics_events(event_type);

create table public.system_logs (
  id          uuid default gen_random_uuid() primary key,
```

## 2.2 Row-Level Security — Migration `0002_rls.sql` (Hardened, O(1))

> [!IMPORTANT]
> **Audit fix H4.** The prior draft used a correlated subquery (`tenant_id in (select tenant_id from profiles where id = auth.uid())`) evaluated **per row** — a performance and correctness foot-gun. The hardened model puts `tenant_id` into the JWT as a custom claim and reads it in O(1) via `auth.jwt()`. `auth.uid()` is wrapped in a scalar subselect so the planner evaluates it once per statement.

```sql
-- ═══════════════════════════════════════════════════════
-- JARVIS v1.5 — Migration 0002: RLS Policies
-- ═══════════════════════════════════════════════════════

-- Helper: current tenant from JWT custom claim (set in 0003 below).
create or replace function public.current_tenant_id()
returns uuid
language sql stable
as $$
  select nullif(auth.jwt() ->> 'tenant_id', '')::uuid
$$;

alter table public.tenants          enable row level security;
alter table public.profiles         enable row level security;
alter table public.chat_sessions    enable row level security;
alter table public.chat_messages    enable row level security;
alter table public.workflows        enable row level security;
alter table public.workflow_runs    enable row level security;
alter table public.integrations     enable row level security;
alter table public.skills           enable row level security;
alter table public.analytics_events enable row level security;
alter table public.system_logs      enable row level security;

-- Profiles: a user sees only their own row.
create policy "own profile" on public.profiles
  for all using (id = (select auth.uid())) with check (id = (select auth.uid()));

-- Tenants: a user sees only their tenant.
create policy "own tenant" on public.tenants
  for all using (id = public.current_tenant_id());

-- Tenant-scoped tables: O(1) claim comparison, no per-row subquery.
create policy "tenant isolation" on public.chat_sessions
  for all using (tenant_id = public.current_tenant_id())
  with check (tenant_id = public.current_tenant_id());
create policy "tenant isolation" on public.chat_messages
  for all using (tenant_id = public.current_tenant_id())
  with check (tenant_id = public.current_tenant_id());
create policy "tenant isolation" on public.workflows
  for all using (tenant_id = public.current_tenant_id())
  with check (tenant_id = public.current_tenant_id());
create policy "tenant isolation" on public.workflow_runs
  for all using (tenant_id = public.current_tenant_id())
  with check (tenant_id = public.current_tenant_id());
create policy "tenant isolation" on public.integrations
  for all using (tenant_id = public.current_tenant_id())
  with check (tenant_id = public.current_tenant_id());
create policy "tenant isolation" on public.skills
  for all using (tenant_id = public.current_tenant_id())
  with check (tenant_id = public.current_tenant_id());
create policy "tenant isolation" on public.analytics_events
  for all using (tenant_id = public.current_tenant_id())
  with check (tenant_id = public.current_tenant_id());

-- System logs: own tenant OR system-wide (null tenant) is readable.
create policy "tenant or system logs" on public.system_logs
  for select using (tenant_id = public.current_tenant_id() or tenant_id is null);
```

### Injecting `tenant_id` into the JWT — Migration `0003_jwt_claim.sql`

Supabase Auth supports a Custom Access Token Hook. Register this function as the hook (Dashboard → Authentication → Hooks) so every issued JWT carries `tenant_id`:

```sql
create or replace function public.custom_access_token_hook(event jsonb)
returns jsonb
language plpgsql stable
as $$
declare
  claims jsonb;
  v_tenant uuid;
begin
  select tenant_id into v_tenant from public.profiles where id = (event->>'user_id')::uuid;
  claims := event->'claims';
  if v_tenant is not null then
    claims := jsonb_set(claims, '{tenant_id}', to_jsonb(v_tenant::text));
  end if;
  return jsonb_set(event, '{claims}', claims);
end;
$$;

grant execute on function public.custom_access_token_hook to supabase_auth_admin;
```

> Until the hook is enabled, `current_tenant_id()` returns null and tenant tables read empty — a safe failure (no leakage). Enable the hook as part of first bring-up (see Part 5 §5.2).

## 2.3 Authentication Model (Audit fix B5)

> [!IMPORTANT]
> **Supabase Auth is the only identity provider. The API never mints its own tokens** — it *verifies* Supabase-issued JWTs. The `JWT_SECRET` env var holds the **Supabase project JWT secret** and is used solely for verification.

```
┌──────────┐   email+password / OAuth    ┌───────────────┐
│  Client  │ ──────────────────────────▶ │ Supabase Auth │
│ (web/app)│ ◀── access + refresh JWT ─── │ (GoTrue)      │
└────┬─────┘                              └───────────────┘
     │  Authorization: Bearer <access_jwt>
     ▼
┌───────────────────────────────────────────────────────┐
│  Fastify API  — middleware/auth.ts                     │
│  1. Extract Bearer token                               │
│  2. Verify signature with JWT_SECRET (Supabase secret) │
│  3. Reject if exp passed / signature invalid → 401     │
│  4. Inject { userId, tenantId, role } into request ctx │
│     (tenantId read from the `tenant_id` claim)         │
└───────────────────────────────────────────────────────┘
```

- **No `/api/auth/register` that mints tokens.** Account creation is `supabase.auth.signUp` on the client; the API exposes only **`POST /api/auth/bootstrap`** (first run) which, inside a transaction, creates the `tenants` row and the `profiles` row for the freshly-signed-up user. All other auth (login, refresh, logout) is handled by the Supabase client SDK directly.
- The middleware verifies the token offline (HS256 with the project secret) — no network round-trip per request.
- `tenant.ts` middleware then guarantees `request.tenantId` is present for every protected route; absence → 401.

## 2.4 The API CRUD Factory (Pillar P2 — Audit fix B2)

> [!IMPORTANT]
> DNA P2 forbids hand-writing CRUD per entity. Standard list/get/create/update/delete are produced by **one factory** driven by a per-entity config. Hand-written handlers exist **only** for non-CRUD verbs (chat streaming, container control, workflow trigger).

### Entity config — `apps/api/src/entities/registry.ts`

```ts
import { z } from "zod";
import { workflowInsertSchema, workflowUpdateSchema } from "@jarvis/shared/schemas";

export interface EntityConfig<TInsert, TUpdate> {
  table: string;                 // Postgres table name (also the cache namespace)
  tenantScoped: boolean;         // inject tenant_id on insert + filter on read
  searchFields: string[];        // columns matched by ?q=
  sortDefault: string;           // e.g. "created_at.desc"
  insertSchema: z.ZodType<TInsert>;
  updateSchema: z.ZodType<TUpdate>;
  softDelete?: boolean;          // sets status='disabled' instead of DELETE where supported
}

export const ENTITIES = {
  workflows: {
    table: "workflows",
    tenantScoped: true,
    searchFields: ["name", "description"],
    sortDefault: "created_at.desc",
    insertSchema: workflowInsertSchema,
    updateSchema: workflowUpdateSchema,
  },
  integrations: { /* ...same shape... */ },
  skills:       { /* ...same shape... */ },
} as const satisfies Record<string, EntityConfig<any, any>>;
```

### The factory — `apps/api/src/factory/crud.ts`

```ts
import type { FastifyInstance } from "fastify";
import type { EntityConfig } from "../entities/registry";
import { ok, paginated, fail } from "../lib/response";   // §2.5 envelope

export function registerCrud(app: FastifyInstance, path: string, cfg: EntityConfig<any, any>) {
  const db = (req: any) => req.supabase;                 // tenant-scoped client (RLS enforced)

  // LIST — GET /api/:path?page=&pageSize=&q=&sort=
  app.get(`/api/${path}`, async (req, reply) => {
    const { page = 1, pageSize = 20, q, sort } = req.query as any;
    let query = db(req).from(cfg.table).select("*", { count: "exact" });
    if (q && cfg.searchFields.length) {
      query = query.or(cfg.searchFields.map(f => `${f}.ilike.%${q}%`).join(","));
    }
    const [col, dir] = (sort ?? cfg.sortDefault).split(".");
    const from = (page - 1) * pageSize;
    const { data, count, error } = await query
      .order(col, { ascending: dir !== "desc" })
      .range(from, from + pageSize - 1);
    if (error) return fail(reply, 500, "DB_ERROR", error.message);
    return paginated(reply, data, { page: +page, pageSize: +pageSize, total: count ?? 0 });
  });

  // GET ONE
  app.get(`/api/${path}/:id`, async (req, reply) => {
    const { id } = req.params as any;
    const { data, error } = await db(req).from(cfg.table).select("*").eq("id", id).single();
    if (error) return fail(reply, 404, "NOT_FOUND", `${cfg.table} ${id} not found`);
    return ok(reply, data);
  });

  // CREATE
  app.post(`/api/${path}`, async (req, reply) => {
    const parsed = cfg.insertSchema.safeParse(req.body);
    if (!parsed.success) return fail(reply, 422, "VALIDATION", "Invalid body", parsed.error.flatten());
    const row = cfg.tenantScoped ? { ...parsed.data, tenant_id: req.tenantId } : parsed.data;
    const { data, error } = await db(req).from(cfg.table).insert(row).select().single();
    if (error) return fail(reply, 500, "DB_ERROR", error.message);
    return ok(reply, data, 201);
  });

  // UPDATE
  app.put(`/api/${path}/:id`, async (req, reply) => {
    const { id } = req.params as any;
    const parsed = cfg.updateSchema.safeParse(req.body);
    if (!parsed.success) return fail(reply, 422, "VALIDATION", "Invalid body", parsed.error.flatten());
    const { data, error } = await db(req).from(cfg.table).update(parsed.data).eq("id", id).select().single();
    if (error) return fail(reply, 500, "DB_ERROR", error.message);
    return ok(reply, data);
  });

  // DELETE (soft where configured)
  app.delete(`/api/${path}/:id`, async (req, reply) => {
    const { id } = req.params as any;
    const op = cfg.softDelete
      ? db(req).from(cfg.table).update({ status: "disabled" }).eq("id", id)
      : db(req).from(cfg.table).delete().eq("id", id);
    const { error } = await op;
    if (error) return fail(reply, 500, "DB_ERROR", error.message);
    return ok(reply, { id, deleted: true });
  });
}
```

### Wiring — `apps/api/src/server.ts`

```ts
import { ENTITIES } from "./entities/registry";
```

## 2.5 Standard Contracts: Response Envelope, Errors, Pagination

> [!IMPORTANT]
> Every API response uses one of these shapes. The types live in `packages/shared/src/types/api.ts` and are imported by **both** the API and the clients — a single contract, no drift (P6).

```ts
// packages/shared/src/types/api.ts
export interface ApiOk<T>        { ok: true;  data: T }
export interface ApiPaginated<T> { ok: true;  data: T[]; page: number; pageSize: number; total: number; hasMore: boolean }
export interface ApiError        { ok: false; error: { code: ErrorCode; message: string; details?: unknown } }
export type ApiResponse<T> = ApiOk<T> | ApiPaginated<T> | ApiError;

export type ErrorCode =
  | "VALIDATION" | "UNAUTHENTICATED" | "FORBIDDEN" | "NOT_FOUND"
  | "RATE_LIMITED" | "DB_ERROR" | "UPSTREAM_ERROR" | "INTERNAL";
```

```ts
// apps/api/src/lib/response.ts — helpers used by the factory + all handlers
export const ok = (reply, data, status = 200) => reply.code(status).send({ ok: true, data });
export const paginated = (reply, data, { page, pageSize, total }) =>
  reply.code(200).send({ ok: true, data, page, pageSize, total, hasMore: page * pageSize < total });
export const fail = (reply, status, code, message, details?) =>
  reply.code(status).send({ ok: false, error: { code, message, details } });
```

| HTTP | `error.code` | When |
|------|-------------|------|
| 401 | `UNAUTHENTICATED` | Missing/invalid/expired JWT |
| 403 | `FORBIDDEN` | Authenticated but role/tenant disallows |
| 404 | `NOT_FOUND` | Resource absent within tenant |
| 422 | `VALIDATION` | Zod parse failed (`details` = flattened issues) |
| 429 | `RATE_LIMITED` | Nginx/Fastify rate limit hit |
| 5xx | `DB_ERROR` / `UPSTREAM_ERROR` / `INTERNAL` | Server/Supabase/Hermes failure |

**Pagination is offset-based** (`page`/`pageSize`, default 20, max 100). Cursor pagination is a documented v2 upgrade for high-volume log/message scans.

**Env validation:** the API validates `process.env` against a Zod schema at boot (`apps/api/src/lib/env.ts`) and refuses to start on missing/invalid vars — fail fast, never half-configured.

## 2.6 Integration Secret Encryption (Audit fix H3)

Provider tokens (GitHub PAT, Vercel token, etc.) are **never** stored in plaintext. They are encrypted with **AES-256-GCM** before insert into `integrations.secret_ciphertext`.

```ts
// apps/api/src/lib/crypto.ts
import { createCipheriv, createDecipheriv, randomBytes } from "node:crypto";
const KEY = Buffer.from(process.env.MASTER_ENCRYPTION_KEY!, "base64"); // 32 bytes; openssl rand -base64 32

export function seal(plaintext: string) {
  const iv = randomBytes(12);
  const cipher = createCipheriv("aes-256-gcm", KEY, iv);
  const ct = Buffer.concat([cipher.update(plaintext, "utf8"), cipher.final()]);
  const tag = cipher.getAuthTag();
  return { ciphertext: Buffer.concat([ct, tag]).toString("base64"), iv: iv.toString("base64") };
}
export function open(ciphertextB64: string, ivB64: string) {
  const raw = Buffer.from(ciphertextB64, "base64");
  const ct = raw.subarray(0, raw.length - 16), tag = raw.subarray(raw.length - 16);
  const decipher = createDecipheriv("aes-256-gcm", KEY, Buffer.from(ivB64, "base64"));
  decipher.setAuthTag(tag);
  return Buffer.concat([decipher.update(ct), decipher.final()]).toString("utf8");
}
```

- `MASTER_ENCRYPTION_KEY` is a required, env-validated 32-byte key (32 bytes base64). It is **not** committed and is rotated by re-sealing all rows.
- Decryption happens only in-process when handing a token to Hermes/MCP; the plaintext never returns to the client (`GET /api/integrations` returns status + masked hints only).
- **Upgrade path:** swap `MASTER_ENCRYPTION_KEY` for **Supabase Vault** (`vault.create_secret` / `vault.decrypted_secrets`) with no schema change — the `seal/open` boundary is the only thing that moves.

## 2.8 WebSocket Contract + Auth Handshake

> [!IMPORTANT]
> **Audit gap closed.** The WS upgrade is authenticated before any event flows.

**Handshake:**
1. Client opens `wss://<host>/ws?token=<supabase_access_jwt>` (browsers can't set headers on WS; the token is passed as a query param over TLS).
2. The API verifies the JWT in the `upgrade` handler **before** accepting the socket. Invalid/expired → `401` and the socket is closed with code `4401`.
3. On success the connection is tagged with `{ userId, tenantId }`; every outbound event is filtered to that tenant.
4. Heartbeat: server `ping` every 30s; client must `pong` within 10s or the socket is closed (`4408`). Client auto-reconnects with backoff (Part 3 §3.4).

**Events (server → client):**
| Event | Payload | Purpose |
|-------|---------|---------|
| `chat:stream` | `{ sessionId, chunk, done }` | Streaming Hermes tokens |
| `chat:tool_call` | `{ sessionId, tool, args }` | MCP tool invocation notice |
| `service:status` | `{ name, status }` | Container health change |
| `workflow:progress` | `{ runId, step, pct }` | Workflow execution progress |
| `log:entry` | `{ level, service, message, ts }` | Real-time log line |
| `notification` | `{ title, message, type }` | Push/toast notification |

**Events (client → server):** `chat:cancel { sessionId }` to abort an in-flight generation; `subscribe { channels[] }` to scope which event types this socket receives.
