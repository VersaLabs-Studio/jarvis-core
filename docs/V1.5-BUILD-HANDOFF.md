## 3. Git Branching Model (phased)

```
main  ──────────────────────────────────────────●  (protected; tagged v1.5.0 at F)
                                                ╱
develop ──●──────●──────●──────●──────●──────●  (integration line for v1.5)
          │PR    │PR    │PR    │PR    │PR    │PR
   phase/a   phase/b  phase/c phase/d phase/e phase/f
      │         │
   feat/a-*  feat/b-crud-factory  feat/b-auth  feat/b-ws ...   (sub-agent branches)
```

### Branch rules
| Branch | Purpose | Merges into | Gate to merge |
|--------|---------|-------------|---------------|
| `feat/<phase>-<package>` | One work package, one Execute sub-agent | `phase/<x>` | Sub-agent **mark-off** DoD (§6) + Code Review on the PR |
| `phase/<x>-<name>` | All packages for a phase | `develop` | Full phase gate (§1) — Auditor ≥ 8.5 |
| `develop` | Integration of completed phases | `main` | Release DoD (§9) |
| `main` | Production | — | Tagged release only; **never direct pushes** |

### Conventions
- **Conventional Commits:** `feat(api): add CRUD factory`, `fix(rls): O(1) tenant claim`, `chore(ci): type-drift guard`. Scope = phase area.
- Every commit trailer: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.
- **One PR per `feat/*` branch.** PR body references the work-package ID (§6) and the Part/section it implements.
- `main` and `develop` are **protected**: PR + passing CI + Code Review approval required. JARVIS/agents **never** push to `main` directly (consistent with Part 1 §1.9).
- Phase branches are short-lived; delete after merge.

## 4. Per-Phase Execution Loop (the DNA lifecycle, applied to each phase)

Run this loop **once per phase**, A→F:

```
Orchestrator ──classify──▶ Plan ──plan doc──▶ [Kidus approves]
     ▼
Execute (fan-out to N sub-agents, one per work package on its feat/* branch)
     ▼  each sub-agent self-marks DoD (§6) → opens PR into phase/*
Code Review (per PR: blockers must clear) 
     ▼
Phase integration on phase/* → run Part 5 phase verification checklist
     ▼
Auditor (scores the integrated phase X.X/10 against the DNA + audit fixes)
     ▼
≥ 8.5 & 0 blockers & green gate ──▶ PR phase/* → develop  (else: required fixes → re-loop)
```

- **Plan first, always.** No Execute sub-agent writes code before the phase plan doc is approved (Orchestrator anti-pattern).
- **Tech Lead** is consulted before Plan when a phase carries a cross-cutting decision (flagged per phase in §5).
- **Debug** is on-call at any point a gate check fails.

## 6. Sub-Agent Mark-Off (Definition of Done per work package)

Every Execute sub-agent **self-certifies** this checklist on its `feat/*` PR before requesting Code Review. Unchecked = not ready; the PR stays in draft.

```
WORK PACKAGE: <id>  ·  IMPLEMENTS: Part <n> §<x>  ·  CLOSES: <audit IDs or none>

[ ] Scope matches the approved plan doc — no scope creep, no out-of-boundary files (P3)
[ ] Types imported from @jarvis/shared (generated) — zero hand-written schema types (P1/P6)
[ ] No `any` in production paths; tsc --noEmit clean (P6)
[ ] Zod validation at every boundary it introduces (P6)
[ ] CRUD goes through the factory; no bespoke CRUD (P2)
[ ] UI work: semantic OKLCH tokens only, skeleton+empty+error states, motion (P4)
[ ] Tests added/updated for this package; they pass locally
[ ] Self-verified against the relevant Part 5 checklist lines
[ ] Conventional commit(s); PR body cites WP id + Part/section + audit IDs closed
[ ] Any deviation from the plan is documented in the PR (P5)
```

> **"Multiple sub-agent mark-off"** = each parallel Execute sub-agent signs the block above; the phase does not integrate until **all** its packages are marked off and individually Code-Reviewed.

## 7. Test · Audit · Verify Strategy

**Three independent layers — none is skippable for a phase merge:**

1. **Test (Execute owns):** unit (Vitest) for factories/crypto/env/RLS helpers; integration (supertest) for API contracts; the **Part 5 phase checklist** as the executable gate; E2E (Playwright web, Expo EAS preview mobile) from Phase C onward.
2. **Audit (Auditor owns):** scored DNA-compliance report per phase. **Merge floor 8.5/10.** The Auditor additionally confirms the relevant **B/H audit IDs** for that phase are closed (§5).
3. **Verify (Kidus + `verify` skill):** human sign-off on the phase gate — run the app, confirm behaviour matches the spec, approve the `phase/* → develop` PR.

**Drift guard runs in CI on every PR** (type generation vs migrations — Part 2 §2.0). A red drift check blocks merge regardless of score.

## 10. Risk Register & Rollback

| Risk | Mitigation | Rollback |
|------|-----------|----------|
| MCP package/model IDs drift (C4/C5) | E3 pins + boot-check; verify at deploy | Disable the affected MCP via compose `profiles`; fallback model chain |
| TLS/domain not ready at F | Run HTTP-only; TLS is an isolated F1 gate | Ship behind HTTP on the VPS, add TLS when DNS lands |
| Phase scores < 8.5 repeatedly | Tech Lead reviews the abstraction; re-plan the package | Keep the phase on `phase/*`; never force-merge |
| Single-VPS outage (H8) | Documented trade-off | `compose up -d` + restore from §5.6 backup (RTO ≈ 30 min) |
| Secret-key exposure | AES-256-GCM, key not committed | Rotate `MASTER_ENCRYPTION_KEY`, re-seal rows |
