# Plan: Full Mobile Responsiveness for JARVIS Dashboard

## Problem Statement

The previous responsive implementation was unsatisfactory. Issues identified:

1. **Inline JavaScript duplication** - Each HTML file has an inline `onclick` handler with the same logic, creating maintenance overhead and inconsistent behavior
2. **Overuse of `!important`** - The CSS uses heavy-handed `!important` declarations that override Tailwind classes, creating specificity wars
3. **Fragmented overlay handling** - The overlay div exists in HTML but the JS also tries to create it, causing confusion
4. **No proper mobile-first structure** - Desktop-first approach with max-width media queries fighting Tailwind's mobile-first utilities
5. **Layout still breaks on mobile** - Header padding, card layouts, tables, and config page don't properly reflow

## Goals

- Clean, mobile-first responsive design that works on all screen sizes
- Proper off-canvas sidebar with overlay (no inline JS)
- Content that reflows gracefully on mobile without `!important` hacks
- Tables that scroll horizontally on mobile
- Touch-friendly UI (16px inputs, adequate tap targets)
- Single source of truth for sidebar logic

## Proposed Approach

### 1. CSS Strategy (custom.css)

**Remove all `!important` declarations.** Instead, rely on:
- Proper media query ordering (mobile-first)
- Tailwind responsive prefixes (`md:`, `lg:`) in HTML where possible
- Custom CSS only for layout-level changes (sidebar positioning)

**Sidebar behavior:**
- Mobile (<1024px): Sidebar is fixed, off-screen left, slides in when toggled
- Desktop (>=1024px): Sidebar is in normal document flow, always visible
- Transition: smooth slide with CSS transform/translateX instead of left property for performance

### 2. JavaScript Strategy (main.js)

**Remove inline JS from all HTML files.** Add a single `data-sidebar-toggle` attribute to the hamburger button. The JS will:
- Find the toggle button by data attribute
- Add proper event listeners (click, touch, resize)
- Manage sidebar state (open/close)
- Handle overlay click, nav link clicks, escape key, swipe gestures
- Clean up properly on page unload

**No inline event handlers** - all interaction logic lives in main.js

### 3. HTML Changes

Each HTML file will have:
- A clean hamburger button: `<button class="mobile-menu-toggle" data-sidebar-toggle aria-label="Toggle menu">...</button>`
- The overlay: `<div class="sidebar-overlay" aria-hidden="true"></div>`
- No inline JS, no inline styles
- Tailwind responsive classes used properly (e.g., `hidden lg:block` patterns)

### 4. Page-Specific Responsive Behavior

| Page | Mobile Behavior |
|------|----------------|
| index.html | Stats cards stack 1 col → 2 cols (sm) → 4 cols (lg). Bento grid 1 col → 2 cols (md) → 3 cols (lg). Header buttons wrap. |
| services.html | Service cards stack vertically. Docker network viz stacks 2 cols → 5 cols. |
| models.html | Model cards stack. Routing config items stack. |
| integrations.html | Integration cards stack. Card header flex wraps. |
| workflows.html | Workflow cards stack. Cron table scrolls horizontally. |
| chat.html | Chat messages full-width. Input area adapts. Quick commands wrap. |
| logs.html | Log controls stack vertically. Log entries scroll horizontally. |
| config.html | File browser stacks above editor on mobile. |
| admin.html | System info grid stacks. Action buttons full-width. |
| analytics.html | Stats cards stack. Charts/bar graphs adapt. |

### 5. Tailwind-First Approach

Instead of overriding Tailwind with custom CSS, leverage Tailwind's responsive prefixes:
- `grid-cols-1 md:grid-cols-2 lg:grid-cols-4` for stats cards
- `flex-col md:flex-row` for layout direction
- `hidden lg:block` for showing/hiding elements
- `p-4 md:p-6 lg:p-8` for responsive padding

Custom CSS should only handle what Tailwind cannot:
- Sidebar positioning/animation
- Touch swipe gestures
- Mobile menu button positioning

### 6. Accessibility

- `aria-label` on menu toggle
- `aria-expanded` managed by JS
- `aria-hidden` on overlay
- Focus trap when sidebar is open
- Escape key closes sidebar

## Implementation Steps
