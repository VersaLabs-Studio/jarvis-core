# Plan: Run JARVIS Core App

## Context
JARVIS Core is a Docker-based autonomous SWE workflow system. It runs via Docker Compose with an OpenClaw gateway and optional MCP servers (GitHub, Vercel, Notion, Browser, Gmail).

## Current State
- `.env` file exists with keys configured (OpenRouter, GitHub, Vercel, Telegram)
- `docker-compose.yml` defines services: `openclaw-gateway`, `mcp-github`, `mcp-vercel`, `mcp-notion`, `mcp-browser`, `mcp-gmail`
- The `openclaw-gateway` image is `openclaw:local` (must be built locally)
- MCP servers use `node:20-slim` images with `npx` commands
- The existing `scripts/docker-start.sh` is designed for Linux (uses `cd ~/openclaw`, `docker compose`)

## Steps

### 1. Check Docker availability
- Run `docker --version` and `docker compose version` to verify Docker is installed and running on this Windows machine.

### 2. Build the OpenClaw gateway image
- The compose file references `image: openclaw:local` — check if a Dockerfile exists for it. If so, build it with `docker build`. If not, this image must already exist or needs to be created.

### 3. Start services with Docker Compose
- Run `docker compose up -d` from the project root (`C:\Users\kidus\Documents\Projects\jarvis-core`).
- This will start `openclaw-gateway` (default profile) and the MCP servers with the `all` profile.
- Use `--profile all` to start everything, or just default for gateway + its dependencies (`mcp-github`, `mcp-notion`, `mcp-vercel`).

### 4. Verify services are running
- Run `docker compose ps` to check container status.
- Run `docker compose logs openclaw-gateway` to check gateway logs for errors.
- The gateway healthcheck hits `http://localhost:18789/health`.

### 5. Confirm app is accessible
- Gateway should be available on port `18789`.
- Verify with `curl http://localhost:18789/health` or similar.

## Notes
- This is a Windows environment; the shell scripts in `scripts/` are bash-based (Linux). We'll use Docker Compose commands directly instead.
- The `openclaw:local` image is the critical dependency — if it doesn't exist and there's no Dockerfile, the gateway won't start.
- Notion, Gmail keys are empty in `.env` — those MCP servers may fail but shouldn't block the gateway.
